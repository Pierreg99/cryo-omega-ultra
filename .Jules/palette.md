## 2024-05-24 - Accessible Tab Implementation
**Learning:** Dynamically generated custom UI components (like tabs) often miss critical accessibility attributes when created as basic `<div>` elements. Without using `<button>` elements or applying explicit `tabindex="0"`, these elements cannot receive keyboard focus, completely alienating users relying on keyboard navigation or screen readers. Furthermore, a visual "active" state must be paired with programmatic feedback like `aria-selected="true"`.
**Action:** When implementing or encountering custom tab interfaces, immediately ensure they are semantic (e.g. `<button role="tab">`), focusable, and communicate their active state programmatically using ARIA attributes (`aria-selected`). Add a `:focus-visible` styling to match the application's default focus outline for visual feedback.
